# 概念科普（可直接内联进 HTML 报告）

> 用途：报告第一章。面向不懂网络基础的读者，全部用类比，不要求任何前置知识。
> 使用时：整章拷进报告，按需删减；把「示例」里的域名换成当次目标的真实数据。

---

## 一、从输入网址到看到画面：四步

```
你输入网址
   ↓
① DNS 解析：把"名字"翻译成"门牌号(IP)"       ← 递归服务器、权威服务器、CNAME、TTL
   ↓
② 调度：决定给你哪一个门牌号                   ← GSLB 调度器、ECS
   ↓
③ 连接：连到那个 IP                            ← 边缘节点
   ↓
④ 分发：机房内部再把请求分给某台机器           ← 负载均衡 CLB
```

后面每个名词，都落在这四步里。

---

## 二、域名与 IP：名字和门牌号

| 概念 | 一句话 | 类比 |
|---|---|---|
| **IP 地址** | 机器真正认的地址，如 `43.135.57.131` | 门牌号 |
| **域名** | 人记得住的名字，如 `www.example.com` | 人名 |
| **DNS** | 把名字翻译成门牌号的系统 | 电话簿 |

浏览器只认 IP，所以每次访问的第一步永远是"翻译"。

## 三、DNS 的三层角色

DNS 不是一个服务器，而是**三级接力**：

| 角色 | 干什么 | 类比 |
|---|---|---|
| **stub resolver + 本地缓存** | 你电脑里的小助手，只记得最近问过的 | 你自己 |
| **递归服务器** | 你委托它去问，它负责跑完全程 | 跑腿代办 |
| **权威服务器** | 只管自己辖区，别的辖区让你去问别人 | 户籍警 |

**关键**：你的电脑不会自己去问全世界，它只问"跑腿的人"。
这个跑腿的通常是运营商 DNS 或公共 DNS（`8.8.8.8` / `223.5.5.5`）。

### 一次真实的四级接力

```
第1跳  问根服务器 "."       → "com 归谁管？"
第2跳  问 "com." 服务器     → "example.com 归谁管？去问 ns-xxx.awsdns-41.com"
第3跳  问权威服务器         → "www 是一个 CNAME，指向 xxx.clb.hk-tencentclb.com"
第4跳  继续追这个新名字     → 最终拿到 IP
```

## 四、三种必懂的记录

| 记录 | 含义 | 类比 |
|---|---|---|
| **A** | 名字 → IP | 户籍档案 |
| **CNAME** | 名字 → 另一个名字（别名） | "去问隔壁老王"的转介条 |
| **NS** | 这个域名归谁管 | 辖区归属 |
| **TTL** | 答案能缓存多少秒 | 保质期 |

**CNAME 是理解 CDN 的钥匙。** 它的语义是："别问我，我不知道 IP，你去问这个名字的主人。"
网站接入 CDN 的标准动作就是加一条 CNAME，**把"回答 IP 的权力"交给 CDN 厂商**。

示例（连续转介）：

```
live.example.com → ffcdn.xyz → txlivecdn.com → dcloudlive.com → 一个 IP
   (客户域名)      (中转域)     (云厂商)        (调度器)
```

## 五、CDN 与边缘节点

想象一家连锁便利店：

| 概念 | 含义 | 类比 |
|---|---|---|
| **源站** | 网站真正的服务器，内容只在这里更新 | 总仓 |
| **边缘节点** | 各地缓存/分发服务器，离用户近 | 最近的门店 |
| **回源** | 边缘没有，向源站要 | 缺货调货 |

**CDN = 同一份内容在很多地方放副本，然后想办法让每个用户拿到最近的那份。**

直播特殊一点：没法"缓存"，边缘节点做的是**实时把流转发给你**，所以节点近不近直接决定卡不卡。

## 六、调度器（GSLB）与 ECS

### GSLB 是什么

普通权威 DNS 是无脑的：谁问都答同一个 IP。
CDN 厂商把它改造成**会看人下菜**的——这就是 **GSLB**（全局负载均衡），俗称**调度器**。

它看什么：地理位置、**运营商**（跨网会卡）、节点健康、节点负载、成本策略。

### ECS 是什么（最抽象的一环）

矛盾：DNS 是"跑腿的"替你问的，权威服务器只看得见跑腿的，**看不见你**。

**ECS（EDNS Client Subnet）** 是让跑腿的在信封上多写一句：
"委托人的网段是 `116.25.0.0/24`，大概在广东电信。"

权威拿到这句，才知道该给广东的节点，而不是给跑腿的所在地的节点。

### 实测（示例）

```bash
dig @119.29.29.29 live.example.com +subnet=116.25.0.0/24   # 说"我在广东电信"
dig @119.29.29.29 live.example.com +subnet=1.2.4.0/24      # 说"我在北京电信"
```

**同一域名、同一秒、两种答案。** 这就是 GSLB + ECS。

> ⚠️ 因此：**单次解析结果只能代表你所在的网络位置**，不能代表全国。
> 报告里必须写"在该解析视角下返回"。

## 七、两个"负载均衡"，别混

| | GSLB（调度器） | CLB（负载均衡器） |
|---|---|---|
| 在哪一层 | **DNS 层** | **机房内部** |
| 解决什么 | 用户该去**哪个机房** | 到了机房，该去**哪台机器** |
| 单位 | 城市/运营商 | 服务器 |

**GSLB 决定"进哪个门"，CLB 决定"进哪间房"。**

## 八、跨境专线：为什么常常与本次分析无关

**跨境专线** = 企业向运营商租的一条私有线路（IEPL / IPLC / MPLS VPN）：
物理隔离、不过公网、稳定低延迟、很贵。它解决的是"两点之间怎么走"。

| | 跨境专线 | VPN | CDN |
|---|---|---|---|
| 本质 | 私有线路 | 加密隧道 | 内容多副本 |
| 谁买 | 企业 | 个人 | 网站运营方 |
| 解决 | 专线互通 | 隐私/绕行 | 就近分发 |

**关键**：网站用了海外 CDN，不等于用户要跨境访问——CDN 会把内容放到离用户近的节点。

## 九、ASN：IP 属于哪个网络

| 概念 | 含义 | 类比 |
|---|---|---|
| **AS / ASN** | 一段 IP 归属的自治网络（如 AS4134=中国电信） | 门牌号属于哪个区 |

**AS 归属 ≠ 机房产权**：国内大量 CDN 节点是"租运营商 IDC 机柜 + 用运营商 IP"，
所以 IP 在 AS4837 不代表联通自建 CDN。

判断口诀：

- **厂商**看 CNAME / NS / 响应头
- **位置**看 ASN / IP 段
- **视角**看你的解析出口
- 三者分开写，不单独下结论

## 十一、自己怎么观察

**不用命令行**：
1. Chrome 开发者工具 → Network → 刷新
2. 看请求的 `Remote Address`，就是真实 IP
3. 换网络（WiFi/4G）再看，IP 常变——那就是调度

**命令行**：

```bash
dig example.com                 # 完整 CNAME 链（别用 +short，会混）
dig +trace example.com          # DNS 逐级接力，教学神器
dig @119.29.29.29 example.com +subnet=1.2.4.0/24   # 模拟从北京解析
whois -h whois.cymru.com " -v 1.2.3.4"              # 查 IP 属于哪个 AS
```

**验证"就近"最直观的办法**：同一台手机，分别用流量和 WiFi 打开同一页面，
对比 `Remote Address`——大概率是两个不同 IP，甚至不同 AS。
